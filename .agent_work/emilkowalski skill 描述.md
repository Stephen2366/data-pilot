12 个 skill 的准确简述

| Skill                          | 特点（一句话）                                               |
| ------------------------------ | ------------------------------------------------------------ |
| `animate`                      | 从零写 Web 动效：先判断该不该动，再定属性/曲线/时长/中断/退出，最后写代码 |
| `animate-expo`                 | React Native/Expo 专用动效（Reanimated、手势、底部弹层、触感） |
| `animation-vocabulary`         | 反向词典："那个弹一下的效果叫啥"→ 给出准确术语；只命名不实现 |
| `apple-design`                 | 苹果式设计原则翻译到 Web：手势、弹簧动效、半透明材质、字体、reduced-motion |
| `ask-sonner`                   | Sonner（React toast 库）使用指南：安装、promise/loading toast、主题、定位 |
| `emil-design-eng`              | UI 打磨哲学总纲：组件细节、动效决策、看不见的细节（animations.dev 那套标准） |
| `find-animation-opportunities` | 只读体检：找出"该动没动"的地方，给精确动效建议，不写代码     |
| `improve-animations`           | 动效审计员：产出分级审计 + 给其他 agent 执行的改进计划，只读不改 |
| `pick-ui-library`              | 查表选库：toast/图表/表格/命令菜单/虚拟化等前端任务该用哪个库，品味向推荐 |
| `prototype`                    | 分歧探索：对同一块 UI 做多个"真正不同"的完整版本，放视觉选择器里翻看、选一个胜者 |
| `review-animations`            | 动效评审：用严格工艺标准审动效代码，默认挑刺、通过要靠挣，不写功能 |
| `write-swift`                  | 现代 Swift 写法（并发、协议泛型、Swift Testing、宏）——iOS 项目用 |
