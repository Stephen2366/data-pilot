# Module Acceptance（模块验收门禁）

## 定位与铁律

本 skill 是模块收工的最后一道门，运行时机在「AI 完成模块 + 写日志 + 用户人工验收和小修小补」**之后**——所以它检查的是 AI 改动与人工改动叠加后的最终状态。

历史教训：曾有"旧路径已清理"的声明写进日志，但 tests/ 里仍有残留。因此铁律只有一条：

> **报告里的每个 ✅ 都必须对应一条本次实际执行过的命令及其输出。不允许凭记忆、凭上文、凭推断打勾。**

执行方式：7 项检查全部跑完再汇总，不要在第一个 ❌ 处停下——验收要一次给出全量结果。所有命令假定在项目根目录执行。项目 Python 路径、外部文档（LEARNING_ROADMAP.md、REFERENCE_GUIDE.md）的位置一律以 CLAUDE.md 顶部为准，不要在本文件里另抄一份。

当前阶段计划文件：优先使用用户指定的计划文件；未指定时，先读 `docs/AI_CONTEXT.md`「当前状态」里的“当前阶段计划文件”，例如 `docs/phase2-plan.md`。下文的“当前阶段计划文件”都指这个文件。

## 检查 1：废弃口径清零

废弃口径登记在本目录 `deprecated-terms.txt`（每行一条 rg 正则），出现即错误：

```bash
rg -n -f .claude/skills/accept-module/deprecated-terms.txt --hidden \
   -g '!.git' -g '!dev-log.md' -g '!AI_CONTEXT.md' -g '!CLAUDE.md' \
   -g '!.agent_work/**' -g '!.claude/skills/accept-module/**' .
```

- 无输出（exit code 1）= ✅；有命中 = ❌，逐条列出 `文件:行` 与命中内容。
- 排除原因：dev-log.md 与 AI_CONTEXT.md 的「模块技术档案」「补充记录」是只追加的历史记录（AI_CONTEXT「当前状态」「已知的坑」的时效性由检查 3 兜底）；CLAUDE.md 的"已废弃口径"登记行是预防层而不是违规；`.agent_work/` 是一次性中间产物快照；skill 目录本身登记了这些词。CLAUDE.md 的路径正确性由检查 2 兜底。
- rg 默认跳过 .gitignore 覆盖的文件。若本次模块改过路径类配置，额外人工看一眼本地 `.env`。

## 检查 2：目录地图一致

Windows / PowerShell 常用：

```powershell
Get-ChildItem -Force | Select-Object Name, Mode
```

macOS / Linux 可用：

```bash
ls -la
```

对照 CLAUDE.md「目录结构」：

- 每个实际存在的可见顶层目录都必须出现在地图中，缺失 = ❌。
- 地图允许包含尚未创建的规划目录（标注"暂定"的部分），不算错。
- `.` 开头的隐藏目录默认豁免；但地图已登记的隐藏目录（如 `.agent_work/temp/`）按地图检查。
- 缓存类目录（`__pycache__`、`.pytest_cache`、`*.egg-info`）豁免。

## 检查 3：进度状态三处一致

读以下三处，确认指向同一个当前模块：

1. 当前阶段计划文件的「模块总览」表：优先找状态为"进行中"的模块；若没有，则第一个"待开始"视为下一模块。已完成模块必须已标"已完成"。
2. `AI_CONTEXT.md`「当前状态」：当前模块与阻塞项。
3. `dev-log.md` 最新一条模块日志的「验证与下一步」。

三者对不上（例如日志说进 M2、总览却还标 M1 进行中）= ❌，指出哪一处没更新。

## 检查 4：最新日志完整性

读 `AI_CONTEXT.md` 最新一节模块技术档案和 `dev-log.md` 最新一条模块日志：

- `AI_CONTEXT.md` 模块档案须含 5 个部分：改动范围、关键决策、参考资料、验证快照、遗留。缺项 = ❌。
- `dev-log.md` 模块日志须含 6 个部分：简述、这次做了什么、新概念、设计要点、面试怎么讲、验证与下一步。缺项 = ❌。
  - 历史日志兼容：旧模块日志里若使用“我该理解什么”承载新概念解释，不因小节名不同判 ❌；但新模块应按 CLAUDE.md 最新模板写“新概念”和“设计要点”。
- 小修复走 `AI_CONTEXT.md`「补充记录」，放宽为：改了什么 / 为什么 / 验证了什么，或等价信息。
- 「验证快照」出现"期待 / 预计 / 预期 / 应该会"这类措辞时，判断是否属于"没跑命令就下结论"，是则 ❌——验证快照必须来自真实执行过的命令 + 真实输出（铁律的日志版）。
- 如果日志中出现“过程细节未记录”，不自动判 ❌。这是 `finish-module` 的防幻觉诚实标记；但如果大量关键决策都未记录，应给 ⚠️，建议后续开发中维护 `.agent_work/temp/<module>-notes.md`。

## 检查 5：注释合规抽查

抽查本模块核心 `.py` 文件。注释是本项目学习和面试复盘的质量要求，因此这是轻量必检项。

抽查规则：

- 如果核心文件少于 3 个，则全部检查。
- 如果核心文件多于 3 个，至少抽查 3 个：
  - 一个主流程文件
  - 一个数据 / 模型 / schema 文件
  - 一个测试或工具文件

检查点：

- 类 / 核心函数是否有 docstring。
- 复杂逻辑是否有步骤注释。
- 外键、relationship、复合索引、安全策略、评测逻辑是否解释“为什么”。
- 是否适当使用 ★ 标记关键点。
- 是否存在大段新代码完全没有解释。

判定（符合以下任一条件即判 ❌，否则 ✅ 或 ⚠️）：

- 抽查文件中，超过 40% 的类或函数缺少 docstring = ❌
- 存在外键、复合索引、多 relationship 但完全没有任何解释 = ❌
- 连续 30 行以上核心逻辑无任何注释 = ❌
- 少量遗漏、个别复杂语句未注释 = ⚠️，列建议即可以

报告中写明抽查了哪些文件和结论。不要为了通过验收临场补代码；发现问题先报告，让用户决定是否回到 `finish-module` 或单独修复。

## 检查 6：单一事实源抽查

每次执行时现场读取当前阶段计划文件的「单一事实源」章节；以后新增权威口径，只需要写进该章节，不需要修改本 skill。

- 权威位置的定义仍然存在、未被改坏。
- 其他文档（本仓库 + CLAUDE.md 顶部链接的两个外部文档）对该口径只有引用或一致表述，没有出现第二份"看起来也像权威定义"的复述。
- 用 rg 抽查，并在报告中给出所用命令，例如核对 smoke 条数：`rg -n "条 smoke|smoke" <相关文档>`。

## 检查 7：真实测试

Windows / PowerShell 常用：

```powershell
$env:PYTHONDONTWRITEBYTECODE='1'
<CLAUDE.md 指定的项目 Python> -m pytest -p no:cacheprovider
```

macOS / Linux 可用：

```bash
PYTHONDONTWRITEBYTECODE=1 "<CLAUDE.md 指定的项目 Python>" -m pytest -p no:cacheprovider
```

把输出最后一行（如 `5 passed in 0.8s`）原样贴进报告。失败 = ❌，附失败用例名。

## 验收报告

聊天中输出下表，并保存一份到 `.agent_work/temp/accept-<模块>-<YYYYMMDD>.md`：

> 当前阶段验收报告先放 `.agent_work/temp/`。如果后续需要把正式验收报告长期保留，再迁到 `eval/reports/`。

```markdown

| # | 检查项 | 结果 | 证据 / 定位 |

| 1 | 废弃口径清零 | ✅/❌ | <命令结论或命中列表> |
| 2 | 目录地图一致 | ✅/❌ | ... |
| 3 | 进度状态一致 | ✅/❌ | ... |
| 4 | 最新日志完整 | ✅/❌ | ... |
| 5 | 注释合规抽查 | ✅/⚠️/❌ | <抽查文件与结论> |
| 6 | 单一事实源 | ✅/❌ | <抽查命令与结论> |

```

有 ❌ 时：给出修复建议；修复完成后**只复跑受影响的检查项**，更新同一份报告并标注"复检"。

## 维护本 skill

- 弃用一个路径 / 名称 / 口径 → 向 `deprecated-terms.txt` 追加一行正则（用 `[/\\]` 兼容两种路径分隔符）。
- 新增权威口径 → 登记进当前阶段计划文件的「单一事实源」即可，检查 6 会在下次执行时读取。
- 非 Claude 的 AI 工具：本文件就是普通 Markdown，从上到下照做即可，铁律同样适用。
