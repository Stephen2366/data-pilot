## 1. 模块定义与范围判断

只写影响模块顺序的最新状态和路线依据，不复述完整 roadmap。

制定计划前先判断本次模块范围是否合适：

- **核心标准** 是方便用户学习、验收和复盘；不要为了工程拆分而拆得过细，导致用户难以形成完整理解，也不要大到执行时容易失控。
- 模块应围绕一个主要问题形成可独立验收的闭环；如果范围过大、包含多个可独立推进的能力或关键验证只能留到后续，请先提出拆分建议。
